## Size interpretation

- Builds produce ABI-specific APKs and omit the universal artifact, avoiding duplicated native runtimes for ARMv7, ARM64, and x86_64.
- Use the per-APK category tables above to compare payloads; native size differs by ABI while shared DEX, assets, and resources are comparable.
- Tectonic, ML Kit OCR, and the Tectonic cache account for most of the remaining native and asset payload.
- The Tectonic cache ships as `assets/tectonic_cache.zip.xz`: a single LZMA2 stream around the bundle archive. The APK compresses assets once, so a deflate-compressed zip could not be packed any further; the XZ form is ~3 MB smaller per ABI and extracts byte-identical files.
- ONNX Runtime uses the reduced `onnxruntime-mobile` build. Its native library is about a fifth of the full build and still covers every operator used by the Magika and MiniLM models.
- Install the APK matching the target device ABI.
- Use release outputs with R8/resource shrinking for size decisions; debug artifacts are larger and are intended for development.
- Further reductions require product decisions such as moving optional OCR functionality to on-demand modules, trimming the LaTeX bundle, or removing a supported ABI.
