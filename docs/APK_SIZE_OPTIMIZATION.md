# APK size optimization

This note records what the release APK payload is made of, which reductions have been applied,
and which candidate reductions were deliberately rejected because they would change behaviour.

The current numbers are generated by `tools/analyze_apks.ps1` and published in
[`APK_ANALYSIS.md`](APK_ANALYSIS.md).

## Result

| Artifact | Before | After | Change |
| --- | ---: | ---: | ---: |
| `app-arm64-v8a-release.apk` | 55.71 MiB | 45.76 MiB | **-17.9 %** |
| `app-armeabi-v7a-release.apk` | 54.18 MiB | 44.67 MiB | **-17.6 %** |
| `app-x86_64-release.apk` | 57.44 MiB | 46.43 MiB | **-19.2 %** |

## Applied changes

### 1. Reduced ONNX Runtime build (-5.1 MB per ABI)

`com.microsoft.onnxruntime:onnxruntime-android` was replaced with
`com.microsoft.onnxruntime:onnxruntime-mobile`, which ships a reduced runtime:

| ABI | `onnxruntime-android` | `onnxruntime-mobile` |
| --- | ---: | ---: |
| arm64-v8a | 18 214 224 B | 3 735 896 B |
| armeabi-v7a | 13 242 304 B | ~2 700 000 B |
| x86_64 | 21 880 016 B | 4 140 256 B |

The mobile build omits a set of operators. Before switching, the operators actually referenced
by both models used in the app were verified against the operators registered in the shipped
native library:

* `assets/magika/model.onnx` uses `MatMul`, `Sqrt`, `Div`, `Mul`, `Add`, `Sub`, `Concat`,
  `Transpose`, `Reshape`, `Slice`, `Shape`, `Cast`, `Expand`, `Equal`, `Unsqueeze`, `Squeeze`.
* The on-demand `all-MiniLM-L6-v2` model used by semantic search uses `MatMul`, `Erf`,
  `Softmax`, `Sqrt`, `Div`, `Mul`, `Add`, `Sub`, `Pow`, `ReduceMean`, `Concat`, `Transpose`,
  `Reshape`, `Gather`, `Slice`, `Shape`, `Cast`, `Constant`, `Unsqueeze`.

All of them are present in the mobile build. The Java API used by the app
(`OrtEnvironment`, `OrtSession`, `OnnxTensor`) is unchanged between the two artifacts for the
members that are actually called.

### 2. Tectonic cache repacked as XZ (-3.1 MB per ABI)

The LaTeX bundle was shipped as `assets/tectonic_cache.zip`. The APK compresses every asset
exactly once, so the zip's own deflate stream could not be compressed any further by the
packaging step: 16.1 MiB of zip cost 13.6 MB inside the APK.

The bundle is now stored as `assets/tectonic_cache.zip.xz`, a single LZMA2 stream around the
same archive, which costs 10.45 MB. The compressor can now see across file boundaries, which
matters because the bundle is mostly small, highly similar TeX source files.

The extraction path in `TectonicCacheManager` unwraps XZ and then the zip; the resulting files
are byte-identical to the previous payload. The repack tool is in
`tools/tectonic-cache/` and re-verifies the round trip every time it runs:

```powershell
.\tools\tectonic-cache\repack.ps1
```

The canonical source archive lives in `tools/tectonic-cache/tectonic_cache.zip`, outside
`app/src/main/assets`, so it is never packaged.

### 3. Unused BouncyCastle tables removed (-1.2 MB per ABI)

`bcprov` ships the constant tables for its Picnic post-quantum key exchange as Java resources
under `org/bouncycastle/pqc/`. The app only uses BouncyCastle through SSHJ for SSH and through
jCIFS for SMB; neither uses Picnic. The tables are now excluded via
`packaging.resources.excludes`.

### 4. Unused font resources removed (-1.0 MB per APK)

`app/src/main/res/font/` contained 17 font files (Bahnschrift, Baloo, Lato, Poppins, Roboto
and friends) totalling roughly 3 MB. Nothing referenced them: no Kotlin source used
`R.font.*`, no layout or style used `@font/...`, and the release build's resource shrinker
confirmed they were unreachable. They have been deleted.

## Rejected candidates

These would each save 1-5 MB but change behaviour, so they were not applied.

* **ML Kit on-device OCR (`com.google.mlkit:text-recognition`)** - about 5.6 MB per APK. The
  unbundled `play-services-mlkit-text-recognition` artifact would remove the OCR pipeline
  native library and the bundled models, but it requires Google Play Services. The app targets
  rooted and de-Googled devices, where OCR would stop working entirely.
* **BouncyCastle R8 keep rules** - roughly 3 600 classes of the 20 000 classes in the DEX come
  from BouncyCastle, and its `BouncyCastleProvider` resolves algorithm implementations by
  string name. Narrowing the keep rules would let R8 strip provider registrations and break
  SSH/SMB crypto at runtime. `bcprov` does not ship its own consumer rules, so the blanket
  keep is required.
* **APKEditor framework stubs (`frameworks/android/android-*.apk`)** - 2.2 MB per APK. The
  merger used by the split-APK merge feature resolves `android:` resource references through
  `ApkModule` -> `AndroidFrameworks` -> `InternalFrameworks`, which loads these stubs.
* **jcodings conversion tables** - 1.3 MB per APK. `org.jruby.jcodings` is pulled in by the
  TextMate language support and loads the tables for CJK encodings on demand.
* **PDFBox/fontbox CMaps** - about 1.2 MB per APK. Required for CJK text extraction from PDFs.
* **Prebuilt Tectonic format file** - the `.fmt` inside the bundle is roughly 4 MB of the
  compressed payload. Tectonic can rebuild it from the bundle on first use, but that path is
  not covered by the offline guarantee the bundled cache provides.
* **Magika model on demand** - 2.9 MB per APK. The model could be downloaded on first use the
  way the semantic-search models already are, but there is no stable public download URL for
  the exact model revision that is bundled here.

## Keeping the size down

* Run `.\tools\analyze_apks.ps1` after any release build; it fails the build if an ABI split
  loses a native library or gains an unexpected one.
* New heavyweight payloads should either be a reduced native build (as with ONNX Runtime) or a
  single compressed stream (as with the Tectonic cache) rather than a pre-compressed archive.
* Do not add dependencies whose native components are needed on only one ABI; ship per-ABI
  splits as the build already does.
